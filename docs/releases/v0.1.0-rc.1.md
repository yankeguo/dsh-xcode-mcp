把 Xcode 的 MCP server **只**挂载进工作目录位于 Xcode 项目内的 DSH 会话。
DSH 没有 workspace 级 MCP 配置（profile 级 `mcp-client` 只能以固定工作目录启动
一个 server），本插件原生补上这个缺口。

**架构：纯 TS 插件，无 Python/uv/fastmcp 依赖，包内不含任何 launcher 脚本。**
插件监听 Agent 注册表，读取每个 Agent 的工作目录，向上发现最近的 Xcode 项目根，
然后通过该 Agent 自己的 Context 加载一个 `mcp-client` 实例，直接以
`xcrun mcpbridge`（Xcode 26+）启动 MCP stdio server，cwd 即发现的项目根。
产生的 `mcp__xcode__*` 工具只对该 Agent 可见。同一批 Agent 还会获得 **Xcode
官方 skills**：插件激活时用 `xcrun agent skills export` 从本机 Xcode 导出到
缓存目录，并经各 Agent 自己的 Context 注册 skill provider——装插件即得，
无需手动安装 skills。

## 亮点

- **按 Agent 挂载**：插件激活时回填已存在的 Agent，之后每个 `agent/created`
  事件都会处理；subagent 拥有自己的 Agent，因此拥有自己独立的 MCP 进程。
- **项目发现**：从会话当前工作目录向上走，返回第一个包含 `*.xcodeproj` 目录的
  祖先目录（符号链接的项目目录同样识别）；会检查 `.git` 根本身然后停止（也会停在
  文件系统根）。同一目录里有多个项目时取字典序第一个。
- **无项目不挂载**：Xcode 项目之外的会话没有 Xcode 工具与 skills，也没有占位 server。
- **内嵌 Xcode 官方 skills**：激活时异步执行 `xcrun agent skills export
  --replace-existing` 导出到 `~/.dsh/cache/dsh-xcode-mcp/skills`（遵循
  `$DSH_HOME`，60s 上限），经每个 Xcode Agent 自己的 Context 注册 skill
  provider（rank 600 / source bundled）。skills 只对 Xcode 工作区会话可见，
  始终匹配本机 Xcode；导出完成后自动 invalidate，会话目录无需重启即刷新。
  包内不分发任何 Apple 内容——全部由用户本机 Xcode 本地生成。`skills: false`
  可关闭。
- **可用性探测**：挂载前用 `xcrun --find mcpbridge` 探测（10s 上限）；Xcode
  缺失或 `mcpbridge` 不可用时跳过挂载与 skills 导出并记录日志，不影响会话。
- **失败隔离**：工作目录缺失、skills 导出失败、MCP 启动失败都只记录日志，
  **绝不会让 Agent 创建失败**；项目树不可读时发现逻辑按“无项目”处理并继续
  向上走（不记录日志）；导出失败时，未被本次导出替换的既有缓存 skills 仍可用。
- **独立进程与干净清理**：每个 Agent 一个 `mcp-client` 子进程；dispose Agent
  或禁用 bundle 会 dispose 对应 fiber 与 skill provider，关闭 stdio 传输、
  移除 skills，子进程随之退出。
- **有界写入**：没有 manifest 文件、没有 Web UI；唯一的文件系统写入是自身
  缓存目录内的 skills 导出。
- **创建时决策**：发现在 Agent 创建时执行一次；本版本中把既有会话移动到别的
  目录（`workingDirectory.set`）不会重新评估挂载。

## 默认配置

| 字段 | 值 |
| --- | --- |
| `serverName` | `xcode` |
| `command` | `xcrun` |
| `args` | `["mcpbridge"]` |
| `env` | `{}` |
| `startupTimeoutMs` | `30000` |
| `skills` | `true` |

cwd 为发现的项目根。所有字段都可通过 profile patch 中 bundle 行的 `config`
覆盖；默认配置在 macOS + Xcode 26+ 上开箱即用，通常无需改动。

当前 `latest` 与 `next` 都指向 `0.1.0-rc.1`；仍建议显式指定版本，以免未来
稳定版发布后行为变化：


或在 Web 的 **Plugins → Add plugin** 中输入
`@yankeguo/dsh-xcode-mcp@0.1.0-rc.1`。
安装后在 Plugins 页面确认 bundle 已启用，刷新 Web 页面。

## 已知限制

- **创建时决策**：移动既有会话的目录不会重新评估挂载；旧项目的 `mcp__xcode__*`
  工具与 skills 会一直附着在该 Agent 上，直到新建 Agent。
- **仅 macOS + Xcode 26+**：依赖 `xcrun mcpbridge`，且使用期间 Xcode 需运行。
- **自定义 launcher 跳过可用性探测**：探测只针对默认的 `xcrun mcpbridge`；
  配置其他 command/args 时由配置者自行保证可用。
- **skills 作用域**：仅 live 的 Xcode 工作区 Agent 可见（cold session 目录不
  含）；provider 注册在 Agent 层，按 registry 的 nearest-layer-wins 规则会在
  Xcode 会话内覆盖全局层同名 skill（包括全局 project/user roots；rank 600 只在
  同一层内参与排序）。
- **skills 依赖 `skills` 服务**：profile 无 skill registry 时子插件静默等待，
  MCP 功能不受影响；skills 导出会写入自身缓存目录（唯一的文件系统写入）。
- 没有 Web UI。
- DSH 升级到 0.3 前需要更新 `engines.dsh` 并做一次回归。
