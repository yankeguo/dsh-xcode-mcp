# v0.1.0 — dsh-xcode-mcp 首个发布

把 Xcode 的 MCP server **只**挂载进工作目录位于 Xcode 项目内的 DSH 会话。
DSH 没有 workspace 级 MCP 配置（profile 级 `mcp-client` 只能以固定工作目录启动
一个 server），本插件原生补上这个缺口。

**架构：纯 TS 插件，无 Python/uv/fastmcp 依赖，包内不含任何 launcher 脚本。**
插件监听 Agent 注册表，读取每个 Agent 的工作目录，向上发现最近的 Xcode 项目根，
然后通过该 Agent 自己的 Context 加载一个 `mcp-client` 实例，直接以
`xcrun mcpbridge`（Xcode 26+）启动 MCP stdio server，cwd 即发现的项目根。
产生的 `mcp__xcode__*` 工具只对该 Agent 可见。

## 亮点

- **按 Agent 挂载**：插件激活时回填已存在的 Agent，之后每个 `agent/created`
  事件都会处理；subagent 拥有自己的 Agent，因此拥有自己独立的 MCP 进程。
- **项目发现**：从会话当前工作目录向上走，返回第一个包含 `*.xcodeproj` 目录的
  祖先目录（符号链接的项目目录同样识别）；会检查 `.git` 根本身然后停止（也会停在
  文件系统根）。同一目录里有多个项目时取字典序第一个。
- **无项目不挂载**：Xcode 项目之外的会话没有 Xcode 工具，也没有占位 server。
- **可用性探测**：挂载前用 `xcrun --find mcpbridge` 探测（10s 上限）；Xcode
  缺失或 `mcpbridge` 不可用时跳过挂载并记录日志，不影响会话。
- **失败隔离**：工作目录缺失、项目树不可读、MCP 启动失败都只记录日志，
  **绝不会让 Agent 创建失败**。
- **独立进程与干净清理**：每个 Agent 一个 `mcp-client` 子进程；dispose Agent
  或禁用 bundle 会 dispose 对应 fiber，关闭 stdio 传输，子进程随之退出。
- **零写入**：没有 manifest 文件、没有 Web UI、不做任何文件系统写入。
- **创建时决策**：发现在 Agent 创建时执行一次；本版本中把既有会话移动到别的
  目录（`workingDirectory.set`）不会重新评估挂载。

## 默认配置

| 字段 | 值 |
| --- | --- |
| `serverName` | `xcode` |
| `command` | `xcrun` |
| `args` | `["mcpbridge"]` |
| `env` | `{}` |
| `startupTimeoutMs` | `30000` |

cwd 为发现的项目根。所有字段都可通过 profile patch 中 bundle 行的 `config`
覆盖；默认配置在 macOS + Xcode 26+ 上开箱即用，通常无需改动。

## 兼容性

- DeepSeek Harness：`>=0.2.1-rc.1 <0.3.0`（`engines.dsh`；已对照
  `dsh-v0.2.1-rc.1` 与 `dsh-v0.2.2-rc.5` 两端 tag 核对所用 API 兼容面，
  运行时实测基准 `0.2.2-rc.5`）。
- Node.js：`>=24.9`（构建与发布工具链）。
- 运行环境：**macOS + Xcode 26 或更新**（`xcrun mcpbridge` 可用，
  `xcode-select` 指向该 Xcode）；使用工具期间 Xcode 需处于运行状态。

## 安装

```sh
dsh plugin --profile desktop add @yankeguo/dsh-xcode-mcp@0.1.0
```

或在 Web 的 **Plugins → Add plugin** 中输入 `@yankeguo/dsh-xcode-mcp`。
安装后在 Plugins 页面确认 bundle 已启用，刷新 Web 页面。

## 验证

- 单元测试 **37 个用例 / 3 个文件**（`pnpm test`）：项目发现（13）、配置校验
  （10）、插件生命周期（14）。
- CI（[`.github/workflows/verify.yml`](../../.github/workflows/verify.yml) 与
  [`.github/workflows/publish.yml`](../../.github/workflows/publish.yml)）在发布前
  跑 `pnpm install --frozen-lockfile` → `pnpm typecheck` → `pnpm test` →
  `pnpm build` → `node scripts/check-packages.mjs`，任何一步失败都不会 stage；
  tag 门禁还会校验 `v*` tag 与根 `package.json` 版本一致。
- 人工验收路径：在工作目录（或其 `.git` 根以内的祖先）含 `*.xcodeproj` 的
  **新**会话里调用 `mcp__xcode__*` 工具（如列出 Xcode 工具或跑一次构建），
  工具只应出现在该会话；在无 Xcode 项目的会话里不应出现；关闭 Agent 或禁用
  bundle 后 `xcrun`/`mcpbridge` 子进程应消失。

## 已知限制

- **创建时决策**：移动既有会话的目录不会重新评估挂载；需要新会话。
- **仅 macOS + Xcode 26+**：依赖 `xcrun mcpbridge`，且使用期间 Xcode 需运行。
- **自定义 launcher 跳过可用性探测**：探测只针对默认的 `xcrun mcpbridge`；
  配置其他 command/args 时由配置者自行保证可用。
- 没有 Web UI；不做任何文件系统写入。
- DSH 升级到 0.3 前需要更新 `engines.dsh` 并做一次回归。
