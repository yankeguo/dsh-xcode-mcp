# v0.1.0 — 首个稳定版

> **稳定版（stable）**。目标 npm dist-tag 为 **`latest`**。本版本通过
> `v0.1.0` tag 触发 CI staged publish；CI 只 stage，不发布。维护者需在 stage
> 成功后手动 approve：
>
> ```sh
> node scripts/promote-release.mjs --version 0.1.0
> ```
>
> 批准后 `0.1.0` 成为 npm 的 `latest`（即不指定版本时的默认安装版本）。
> 批准前 `latest` 仍指向已公开的 `0.1.0-rc.3`，npm 上不存在 `0.1.0`。

这是 `@yankeguo/dsh-xcode-mcp` 的第一个稳定版。`0.1.0` 的插件代码与已公开的
`0.1.0-rc.3` 相同（在 rc.3 的 commit 之上只改版本号与文档，没有代码变更）；
rc.3 之后的稳定化只涉及版本与发布元数据，没有行为变更。`0.1.0-rc.2` 曾成功
stage 但 staged 记录随后被 reject，**从未发布**；rc.3 取代了它。完整审计记录见
[`docs/AUDIT.md`](../AUDIT.md)，兼容矩阵见 [`docs/COMPATIBILITY.md`](../COMPATIBILITY.md)。

## 功能概览

插件发现 Session 工作目录所在的 Xcode 项目后，直接以 `xcrun mcpbridge` 为该
Agent 启动 MCP stdio server，并导出 Xcode 官方 skills；纯 TypeScript，无
Python/uv/launcher 脚本依赖。

- **按 Agent 挂载**：现有 Agent 在插件激活时并发 backfill，之后每次
  `agent/created` 都处理；创建 Agent 会等待完整 attach task。只在 Xcode 项目内
  的 Session 出现 `mcp__xcode__*` 工具与 Xcode skills。
- **项目发现**：从 Session 工作目录向上找最近的、包含 `*.xcodeproj` 目录的
  祖先，止于 `.git` 根或文件系统根。
- **skills 导出**：每次激活执行一次 `xcrun agent skills export
  --replace-existing` 到自有缓存目录，经 Agent 自己的 Context 注册；导出成功
  才替换缓存，新导出落地后无需重启即可刷新。
- **失败隔离**：缺目录、probe 失败、导出失败、MCP 启动失败都只记录诊断，不会
  让 Agent 创建失败。
- **有界写入 / 干净 teardown**：无 manifest 文件、无 Web UI，唯一文件系统写入
  是自身的 skills 缓存目录；dispose Agent 或禁用 bundle 会关闭子进程并移除
  skills。

## 自 rc.1 以来进入本版本的内容

### DeepSeek 独立审计修复

- **Apple skills 路由提示**：同时接受 Apple 的 `when_to_use` 与 DSH 的
  `whenToUse`，不再静默丢弃 routing hint。
- **backfill 与 `agent/created` 竞态**：复用 in-flight attach task，serial
  creation 不再先于工具注册完成。
- **看门狗与卸载硬化**：拒绝 `startupTimeoutMs: NaN`/小数；backfill 期间卸载
  不再等满 30s；看门狗 abort-aware 且定时器 `unref()`。
- **环境与 Xcode 选择**：`$DSH_HOME` 的空值/`~`/相对路径按 DSH 规则处理；
  `config.env` 与自定义 xcrun 路径同时用于 probe/export，非 xcrun launcher
  回退 system xcrun。
- **skill 读取诊断**：list/get 路径只把 `ENOENT`/`ENOTDIR` 当缺失，EACCES/EISDIR
  等真实错误经 logger warn，不再静默。
- **发布与平台元数据**：`dsh.bundle.platforms: ["darwin"]`；peer ranges 覆盖
  rc.1 的 cordis 4.0.5 / schemastery 3.18.5；文档按真实 npm/CI 状态修正。

### rc.2 之后的复核 follow-up

- **创建取消**：共享 attach task 增加 per-task `AbortController`；creation
  signal abort 时同时中止 mount/probe task，并 dispose 已挂载的 handshake。
- **`loadExportedSkill` 读取诊断**：get 路径的真实读取错误经 provider logger
  warn，并通过真实 skill registry 的 `skills.get` 断言 warning。
- **集成测试**：验证 `startAutoloader` 确实把 `config.env` 传给 probe/export，
  自定义 xcrun 路径复用，非 xcrun launcher 回退 system xcrun。
- **测试与兼容性收尾**：provider warning/invalidator 清理、export 中途卸载、
  mount handshake 取消 dispose；新增 `docs/COMPATIBILITY.md`，明确 DSH 0.2.1
  忽略 platform 字段、Node 24 CI 覆盖、Node 26 仅本地、Node 22.19 未验证。

## 安装

**批准（promote）之后**，`0.1.0` 是 `latest`，可省略版本安装：

```sh
dsh plugin --profile desktop add @yankeguo/dsh-xcode-mcp
# 或精确指定版本：
dsh plugin --profile desktop add @yankeguo/dsh-xcode-mcp@0.1.0
```

或在 Web 的 **Plugins → Add plugin** 中输入 `@yankeguo/dsh-xcode-mcp`。批准前
npm 上不存在 `0.1.0`，请继续使用已公开的
`@yankeguo/dsh-xcode-mcp@0.1.0-rc.3`。

首次在 Session 内使用 Xcode 工具时，先调用
`mcp__xcode__XcodeOpenWorkspace`（项目绝对路径）并在 Xcode 中批准授权；在此之前
其他 Xcode 工具会返回未授权错误。Xcode 需处于运行状态。

## 兼容性

- DeepSeek Harness：`>=0.2.1-rc.1 <0.3.0`（运行时基准 `0.2.2-rc.5`；API 兼容面
  已核对 rc.1 与 rc.5 两端 tag）。DSH 0.2.1 忽略 `dsh.bundle.platforms`，仍靠
  xcrun probe 兜底；0.2.2+ 才由 Host 强制 macOS 限制。
- Node.js：`>=24.9`；CI 只 pin Node 24，Node 26 仅本地验证，Node 22.19 未验证。
- 运行环境：**macOS + Xcode 26 或更新**；使用工具期间 Xcode 需运行。

## 已知限制

- **创建时决策**：发现与挂载只在 Agent 创建时执行；`workingDirectory.set` 不会
  重新评估，旧项目的工具/skills 会附着到该 Agent 重建为止。瞬时失败不重试。
- **残余竞态**：插件激活时若某个 Agent 的 `agent/created` 派发已开始（监听器
  快照已定），backfill 可能无法被创建路径等待；DSH 没有 announcement barrier。
- **config restart**：Cordis restart 不触发 `internal/plugin`；restart 时若
  backfill 挂载卡住，仍需等看门狗。
- **非 abort 子步骤**：bridge probe 上限 10s；discovery 无超时，项目树在挂死的
  网络卷上仍可能拖慢创建/卸载。
- **只识别 `*.xcodeproj`**：`.xcworkspace`-only 仓库不会挂载（当前公开契约）。
- **自定义 launcher**：非默认 command/args 跳过可用性预检，由 mcp-client 自行
  验证。
- `toolCallTimeoutMs` 未暴露；大构建可在自定义 mcp-client 设置中调整。
- 没有 Web UI；唯一的文件系统写入是自身的 skills 缓存目录。
